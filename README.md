# THE CONSTRUCT

Matrix-style first-person shooter. Game core in Rust compiled to WebAssembly,
rendered with three.js.

**Play it:** https://the-construct.kevin-128.workers.dev

Arrow keys or WASD to move, mouse to look, click to fire, shift to sprint.
Terminate every agent to clear the level.

```
core/src/lib.rs     Rust game core: world gen, movement + collision, enemy AI,
                    raycast hit detection, waves, particles, digital rain
site/               everything that gets deployed
site/index.html     thin three.js renderer that reads the core's f32 buffers
site/index-js.html  the original pure-JavaScript version, kept for comparison
site/pkg/           wasm-bindgen output (generated by build.sh)
build.sh            cargo build --target wasm32 + wasm-bindgen
wrangler.jsonc      Cloudflare Workers static-assets config
```

## Run

```sh
./build.sh                       # needs: rustup target add wasm32-unknown-unknown
                                 #        cargo install wasm-bindgen-cli --version 0.2.128
python3 -m http.server 8765 -d site   # any static server that serves .wasm
# open http://localhost:8765/
```

## Deploy to Cloudflare

Served as a Worker with static assets (no Worker script, just files).

```sh
npm install
npx wrangler login       # once
npm run deploy           # builds the wasm, then wrangler deploy
```

`npm run dev` serves `site/` locally through wrangler.

## Test

```sh
cd core && cargo test
```

## How the split works

Each frame JS calls `game.step(dt, forward, right, sprint)` and gets back an
event bitmask (wave started, hit, kill, death, damage). It then builds
`Float32Array` views over WASM linear memory for the state, enemy, particle
and rain buffers and copies them into three.js objects. Mouse deltas go to
`game.look()`, clicks call `game.fire()`, which raycasts against buildings and
agents in Rust and writes the impact point for the tracer. No per-frame object
allocation crosses the boundary; everything is flat f32 buffers and numbers.
